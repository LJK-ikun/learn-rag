# 05 混合检索（M5b）

## 为什么做这件事

**单一检索路径有盲区**：

- **纯向量检索**：擅长语义理解（"图结构快不快"能匹配到"HNSW 查询性能"），但对**精确术语**不敏感 —— 用户问"BM25"，向量可能召回一堆"检索算法"但漏掉真正提到"BM25"的那段。
- **纯关键词检索**：擅长精确匹配，但不懂同义词、改写 —— 用户问"那个图的东西"，关键词检索完全抓瞎。

**混合检索**：两路都跑，用 RRF（Reciprocal Rank Fusion）融合排名 —— 在两路都排前面的文档会得到更高的最终分数，单路命中的也保留（分数较低）。

## 改了什么

### 1. 新增 BM25 索引（`store.py`）

**构建**：
```python
def _tokenize(text: str) -> list[str]:
    """中文按字符切分，保留字母数字（术语如 HNSW、BM25）"""
    # 例："HNSW 的 M 参数" -> ["HNSW", "的", "M", "参数"]
    
def _build_bm25_index(chunks: list[Document]) -> BM25Okapi:
    tokenized_corpus = [_tokenize(doc.page_content) for doc in chunks]
    return BM25Okapi(tokenized_corpus)
```

**持久化**：
```python
def _save_bm25_index(bm25: BM25Okapi) -> None:
    path = config.INDEX_DIR / "bm25.pkl"
    with open(path, "wb") as f:
        pickle.dump(bm25, f)
```

BM25 索引和向量库一样：指纹没变就读盘，变了就重建。

### 2. RRF 融合算法（`store.py`）

```python
def _rrf_fusion(
    results_list: list[list[tuple[Document, float]]], k: int = 60
) -> list[tuple[Document, float]]:
    """对每个 doc，RRF 分数 = Σ 1/(k + rank_in_each_list)"""
```

**原理**：
- 在多路都排前面的 doc → RRF 分数高
- 只在单路出现的 doc → 保留但分数低
- `k=60` 是平滑参数（经验值，防止排名1的权重过大）

---

### 3. 两阶段检索（`store.py`）

```python
def search(
    vector_store: Chroma,
    bm25: BM25Okapi,
    chunks: list[Document],
    query: str,
    k: int | None = None,
) -> list[tuple[Document, float]]:
    fetch_k = config.FETCH_K  # 20
    final_k = k or config.TOP_K  # 5
    
    # 1. 向量检索：召回 20 个
    semantic_results = vector_store.similarity_search_with_score(query, k=fetch_k)
    
    # 2. BM25 检索：召回 20 个
    query_tokens = _tokenize(query)
    bm25_scores = bm25.get_scores(query_tokens)
    ranked_indices = sorted(
        range(len(bm25_scores)), key=lambda i: bm25_scores[i], reverse=True
    )[:fetch_k]
    bm25_results = [(chunks[i], bm25_scores[i]) for i in ranked_indices]
    
    # 3. RRF 融合
    fused = _rrf_fusion([semantic_results, bm25_results])
    
    # 4. 取前 5 个
    return fused[:final_k]
```

**为什么分两阶段**：
- 第一阶段（FETCH_K=20）：每路多召回一些候选，给融合算法足够的选择空间
- 第二阶段（TOP_K=5）：融合后只取前 5 个返回给用户，保持结果紧凑

---

### 4. API 改造

**之前**：`store` 是单一对象，`search(store, query, k)`

**现在**：`store` 变成元组 `(vector_store, bm25)`，`search(vector_store, bm25, chunks, query, k)`

**连锁改动**：
- `store.load_or_build_store(chunks)` → 返回 `(Chroma, BM25Okapi)`
- `tools.build_tools(vector_store, bm25, chunks, sources)` → 接受三个参数
- `agent.build_agent(vector_store, bm25, chunks)` → 接受三个参数
- `main.py` → 解包元组：`vector_store, bm25 = load_or_build_store(chunks)`
